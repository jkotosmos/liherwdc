# OPERON на двух серверах: базы в РФ, приложение за рубежом

Сервер баз (в РФ) хранит MongoDB сайта и Qdrant («Квант»). Сервер приложения
(за рубежом, откуда открыт Telegram) держит сайт базы знаний, бот OPERON и HTTPS.
Между ними — приватный канал WireGuard; из интернета базы не видны.

| | Сервер баз | Сервер приложения |
|---|---|---|
| Адрес в канале | 10.8.0.1 | 10.8.0.2 |
| Что работает | MongoDB 7, Qdrant 1.19.2 | бэкенд и фронтенд сайта, бот, Caddy |
| Открыто наружу | SSH; 51820/udp — только для IP сервера приложения | SSH, 80, 443 |
| Папка | `deploy/split/db` | `deploy/split/app` |
| Мощность | от 2 ГБ памяти, 20 ГБ диска | от 4 ГБ памяти (сборка фронтенда), 40 ГБ диска |

Сервер баз лучше держать в Москве или Петербурге: сайт делает много запросов
к базе, и каждый идёт через канал. Задержку проверьте после шага 1:
`ping -c 5 10.8.0.1` с сервера приложения (желательно до 60 мс).

## Доступы — по минимуму

| Кто | MongoDB | Qdrant |
|---|---|---|
| Сайт | `operon_app` — чтение и запись базы `operon` | полный ключ `QDRANT_API_KEY` |
| Бот OPERON | `operon_bot` — только чтение базы `operon` | ключ только на чтение `QDRANT_READ_KEY` |
| Администратор | `root` — только для обслуживания | — |

Пользователи MongoDB создаются при первом запуске (`db/initdb/01-users.js`).
Пароли — только латиница и цифры (`openssl rand -hex 24`): они идут в адрес подключения.

## Установка

На обоих серверах (Ubuntu 24.04, от root):
```sh
git clone -b main https://github.com/jkotosmos/liherwdc.git /opt/operon
cd /opt/operon/deploy/split
```
Обязательно `-b main`: ветка репозитория по умолчанию — другая, в ней нет `deploy/`.
Если `/opt/operon` уже есть (клон на другой ветке), переключите его, ничего не удаляя —
папки с данными и `.env` git не трогает:
```sh
git -C /opt/operon fetch origin main && git -C /opt/operon checkout -B main origin/main
```

### 1. Канал WireGuard (три команды, ключи создаются на месте)
```sh
# Сервер баз:
sh wireguard.sh db <публичный IP сервера приложения>      # напечатает КЛЮЧ_БАЗ
# Сервер приложения:
sh wireguard.sh app <публичный IP сервера баз> <КЛЮЧ_БАЗ>  # напечатает КЛЮЧ_ПРИЛОЖЕНИЯ
# Сервер баз:
sh wireguard.sh peer <КЛЮЧ_ПРИЛОЖЕНИЯ>
# Проверка с сервера приложения:
ping -c 5 10.8.0.1
```
Скрипт ставит WireGuard, включает его при загрузке, запускает Docker на сервере
баз после канала и открывает 51820/udp только для сервера приложения (ufw; SSH остаётся открыт).

Порядок важен: `setup.sh` на сервере приложения запускается только после всех трёх
команд — до шага `peer` базы через канал недоступны, и он остановится с ошибкой.
Сервер баз можно запустить (шаг 2) сразу после `wireguard.sh db`: шаг `peer` применяется
без перезапуска канала.

### 2. Сервер баз
```sh
cd /opt/operon/deploy/split/db
cp .env.example .env && nano .env      # пароли и ключи
sh setup.sh
```

### 3. Сервер приложения
```sh
cd /opt/operon/deploy/split/app
cp .env.example .env                   # домены + те же пароли и ключи, что на сервере баз
cp ../../timeweb/backend.env.example backend.env   # или готовый backend.env
cp ../../timeweb/bot.env.example bot.env           # или готовый bot.env
nano .env backend.env bot.env
sh setup.sh
```
`setup.sh` проверит файлы, токены ботов и доступ к базам через канал, скачает код сайта и запустит всё.
Адреса баз, пароли MongoDB и ключи Qdrant в `backend.env` и `bot.env` писать не нужно —
их подставляет `docker-compose.yml` из `.env`.

## Проверка
- `docker compose ps` на обоих серверах — всё Up.
- С сервера приложения: `nc -zv 10.8.0.1 27017` и `nc -zv 10.8.0.1 6333` — открыто.
- С любого другого компьютера порты 27017 и 6333 сервера баз закрыты.
- `https://<KB_DOMAIN>` открывается, вход администратора по коду из почты работает.
- В Telegram боту: `/check` — «База сайта (MongoDB)» и «Квант» без ❌.

## Обслуживание
- Обновить приложение: `cd deploy/split/app && sh setup.sh`; только бота: `docker compose up -d --build bot`.
- Резервная копия базы (на сервере баз):
  `docker compose exec -T mongo sh -c 'mongodump -u "$MONGO_INITDB_ROOT_USERNAME" -p "$MONGO_INITDB_ROOT_PASSWORD" --authenticationDatabase admin --db operon --archive' > operon-$(date +%F).archive`
- Снимок «Кванта»: `curl -X POST -H "api-key: $QDRANT_API_KEY" http://10.8.0.1:6333/collections/knowledge_base/snapshots`.
- Канал: `wg show` — видно последнее рукопожатие с другим сервером.

## Что где хранится
- MongoDB (пользователи сайта и агента, роли, темы, сообщения) и «Квант» — на сервере баз, в РФ.
- Данные бота OPERON (`app/data/bot`: история диалогов, поручения, напоминания, входы Google) —
  на сервере приложения. Если их тоже нужно держать в РФ, это отдельная задача.
