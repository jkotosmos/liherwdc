# Развёртывание на Amvera Cloud

Приложение собирается по `Dockerfile`, поэтому окружение на сервере совпадает
с локальным. Всё изменяемое состояние лежит на постоянном диске `/data` и
переживает передеплой.

## Что понадобится

| Что | Где взять | Обязательно |
|---|---|:---:|
| Ключ RouterAI | личный кабинет [routerai.ru](https://routerai.ru/) | **да** |
| Точное имя модели | покажет `python -m app.probe` из вашего каталога | **да** |
| Пароль на вход | придумываете сами | **да** |
| Парольная фраза для токена | придумываете сами (`OPERON_TOKEN_KEY`) | **да** |
| Проект в Amvera | панель Amvera → «Создать проект» | **да** |
| Токен Telegram-бота | [@BotFather](https://t.me/BotFather) | **да** |
| Свой Telegram ID | [@userinfobot](https://t.me/userinfobot) | **да** |
| OAuth-клиент Google | Google Cloud Console → Credentials | для Диска и календаря |
| Ключ поискового API | Tavily / Brave / Serper / Google CSE | для интернета |
| Документы базы знаний | ваши файлы (`.md`, `.csv`, `.json`) | позже |

### Где именно брать каждый ключ

**1. RouterAI — доступ к модели.** Личный кабинет на
[routerai.ru](https://routerai.ru/) → раздел с API-ключами → создать ключ.
Вид: `sk-…`. Оплата из России, совместим с API OpenAI, адрес и протокол
подставляются автоматически. Кладётся в `ROUTERAI_API_KEY`.

Ключ виден один раз при создании — сохраните сразу. Утёк (попал в переписку,
скриншот, репозиторий) — перевыпустите: это дешевле разбирательств со счётом.

**2. Имя модели — не ключ, но без него не стартует.** У шлюза свой каталог,
угадывать нельзя. `python -m app.probe` с вашей машины выведет список и
проверит вызов инструментов. Кладётся в `OPERON_MODEL`.

**3. Telegram — токен бота.** В Telegram напишите
[@BotFather](https://t.me/BotFather) → `/newbot` → имя и адрес бота (адрес
должен заканчиваться на `bot`). В ответ придёт строка вида
`1234567890:AAH…`. Кладётся в `TELEGRAM_BOT_TOKEN`.

Потерялся — `/mybots` → бот → *API Token* → *Revoke current token*.

**4. Telegram — свой ID.** Напишите [@userinfobot](https://t.me/userinfobot)
любое сообщение, он ответит числом. Кладётся в `TELEGRAM_ALLOWED_USERS`
(несколько — через запятую).

Это **не ключ, а единственная граница безопасности всей системы**: бот
работает с вашим Google-аккаунтом и вашим бюджетом API. Без белого списка
бот не запускается, и это намеренно.

**5. Google — OAuth-клиент (файл, а не ключ).**
[console.cloud.google.com](https://console.cloud.google.com/) →

1. создать проект (или выбрать существующий);
2. **APIs & Services → Library** → включить **Google Drive API** и
   **Google Calendar API**;
3. **OAuth consent screen** → тип **External** → заполнить название и почту →
   **Publish app** (статус станет *In production*). **На верификацию не
   подавать** — она нужна публичным приложениям со многими пользователями.
   Статус *Testing* оставлять нельзя: согласия в нём протухают через 7 дней;
4. **Credentials → Create credentials → OAuth client ID**. Дальше зависит
   от типа клиента — **это решение определяет весь остальной сценарий**:

**Вариант A — «Web application» (рекомендуется).** В поле **Authorized
redirect URIs** добавьте ровно:

```
https://<ваш-проект>.amvera.io/oauth2/callback
```

Тогда `/auth` работает в одно нажатие: разрешили доступ — код пришёл на
сервер сам, копировать нечего. Адрес должен совпадать посимвольно, иначе
Google ответит `redirect_uri_mismatch`.

**Вариант B — «Desktop app».** Ничего регистрировать не нужно, но после
согласия придётся скопировать адрес из строки браузера и отправить его боту.
Включается, когда `OPERON_PUBLIC_URL` не задан либо когда
`OPERON_OAUTH_REDIRECT_URI` указывает на localhost.

Полученные **Client ID** и **Client secret** задайте переменными окружения:

```
GOOGLE_CLIENT_ID       <...apps.googleusercontent.com>
GOOGLE_CLIENT_SECRET   <GOCSPX-...>
```

Так на постоянный диск ничего загружать не нужно. Альтернатива — скачать
JSON, переименовать в `client_secret.json` и положить в `/data/credentials/`.

`client_secret` — настоящий секрет. В репозиторий он не попадает
(`.gitignore` исключает `client_secret*.json`), и **приватность репозитория
не делает его подходящим местом для секретов**: место секретов — переменные
окружения. Утёк — сбросьте в консоли (*Reset secret*).

**6. Поиск в интернете — любой один ключ.** Через сторонний шлюз серверный
поиск Anthropic недоступен, поэтому нужен собственный поставщик. Порядок
выбора автоматический: Tavily → Brave → Serper → Google CSE; принудительно
задаётся через `OPERON_SEARCH_PROVIDER`.

| Поставщик | Где взять | Переменные |
|---|---|---|
| **Tavily** (проще всего) | [tavily.com](https://tavily.com/) → регистрация → API Keys | `TAVILY_API_KEY` |
| Brave Search | [brave.com/search/api](https://brave.com/search/api/) → подписка на план | `BRAVE_API_KEY` |
| Serper | [serper.dev](https://serper.dev/) → регистрация → Dashboard | `SERPER_API_KEY` |
| Google CSE | [console.cloud.google.com](https://console.cloud.google.com/) (ключ) + [programmablesearchengine.google.com](https://programmablesearchengine.google.com/) (движок) | `GOOGLE_CSE_KEY` + `GOOGLE_CSE_ID` |

У всех четырёх есть бесплатный уровень, но лимиты и условия меняются —
смотрите актуальные на сайте поставщика. Tavily сделан под задачи агентов:
возвращает готовые выдержки, а не список ссылок.

Без ключа поиска агент не выдумывает, а честно сообщает, что интернет-поиск
не настроен, — но пункт ТЗ про внешние данные будет закрыт лишь наполовину.

**7. Два секрета, которые вы придумываете сами.**

| Переменная | Зачем | Что будет, если потерять |
|---|---|---|
| `OPERON_ACCESS_PASSWORD` | пароль на вход в веб-чат | задать новый в панели |
| `OPERON_TOKEN_KEY` | шифрует токен Google на диске | токен не расшифруется, спасёт только новый `/auth` |

`OPERON_TOKEN_KEY` **запишите в надёжном месте сразу**. Шифрование защищает
от утёкшего бэкапа диска, но не от скомпрометированного процесса: ключ лежит
в переменных окружения той же машины. Полезно, но не переоценивайте.

`OPERON_SESSION_SECRET` задавать не нужно — сгенерируется и сохранится на
диск при первом запуске.

### Проверка перед развёртыванием

RouterAI совместим с API OpenAI, адрес подставляется сам — достаточно ключа.
Убедитесь, что выбранная модель умеет вызывать инструменты:

```bash
export ROUTERAI_API_KEY=ваш-ключ
python -m app.probe
```

Проверка выведет каталог моделей вашего аккаунта, определит протокол и —
главное — покажет, работает ли **вызов инструментов**. Без него агент
бесполезен: он не сможет ни искать в базе знаний, ни спрашивать
подтверждение. Выберите модель из списка (у Claude вызов инструментов
поддерживается) и укажите её в `OPERON_MODEL`.

Если используете не RouterAI, а другой шлюз, задайте `OPERON_LLM_BASE_URL`
и `OPERON_LLM_API_KEY` — та же проверка подберёт протокол.

## Шаг 1. Переменные окружения

Есть два способа, они равнозначны и сочетаются.

**Способ А — файлом.** Положите файл с именем `.env` в корень постоянного
диска (панель Amvera → **Данные** → загрузить в `/data`). Приложение читает
его при старте и пишет в лог, откуда взяло настройки. Так быстрее и меньше
шансов ошибиться, чем вводить полтора десятка переменных по одной. Файл
переживает передеплой; в git он не попадает (`.gitignore`).

Путь можно переопределить переменной `OPERON_ENV_FILE`.

**Способ Б — панелью.** Проект → **Переменные окружения**. Заданное здесь
**сильнее файла** — удобно, чтобы поменять одно значение, не трогая остальное.

Минимальный набор:

```
ROUTERAI_API_KEY         <ключ RouterAI>
OPERON_MODEL             <имя модели из app.probe>
OPERON_ACCESS_PASSWORD   <ваш пароль на веб-чат>
OPERON_TOKEN_KEY         <парольная фраза для шифрования токена Google>
TELEGRAM_BOT_TOKEN       <токен от @BotFather>
TELEGRAM_ALLOWED_USERS   <ваш Telegram ID от @userinfobot>
OPERON_PUBLIC_URL        https://<проект>.amvera.io
OPERON_ORG_NAME          OPERON
OPERON_TIMEZONE          Europe/Moscow
TAVILY_API_KEY           <ключ поиска, если нужен интернет>
```

Адрес (`https://routerai.ru/api/v1`) и протокол (`openai`) для RouterAI
подставляются автоматически — задавать их не нужно.

`OPERON_HOST`, `OPERON_PORT` и пути к данным уже заданы в `Dockerfile` —
задавать их в панели не нужно.

> Без `OPERON_ACCESS_PASSWORD` приложение **откажется запускаться** на внешнем
> адресе. Это намеренно: на сервере хранится OAuth-токен вашего Google-аккаунта,
> и чат без пароля означал бы открытый доступ к вашим документам и календарю.

## Шаг 2. Загрузка кода

Amvera даёт git-репозиторий проекта. Из каталога с кодом:

```bash
git remote add amvera https://git.amvera.ru/<логин>/<проект>
git push amvera claude/operon-ai-agent-06p9uw:master
```

Сборка стартует автоматически. Следите за ней во вкладке **Сборка**;
после успеха приложение поднимется на `https://<проект>.amvera.io`.

## Шаг 3. Проверка

```bash
curl https://<проект>.amvera.io/api/health          # состояние, всегда 200
curl -i https://<проект>.amvera.io/api/health?strict=1   # 503, если бот мёртв
```

Проверка отвечает без пароля и показывает не только веб, но и бота:

```json
{"status": "ok", "web": "ok",
 "telegram": {"running": true, "restarts": 0, "last_error": ""}}
```

`status: degraded` означает, что бот настроен, но не работает; причина —
в `last_error`, число подъёмов — в `restarts`. Обычный вызов всегда отдаёт
200 (это проверка живости процесса), а `?strict=1` в той же ситуации отдаёт
503 — его и стоит подключать к внешнему мониторингу. Разделение намеренное:
если бы контейнер перезапускался по неверному токену Telegram, он ушёл бы в
бесконечный цикл, а перезапуском бота и так занимается надзор внутри процесса.

Откройте адрес в браузере: появится страница входа. После пароля —
чат. В шапке видно провайдера, число документов и состояние Google.

## Шаг 4. База знаний

Каталог базы знаний на сервере — `/data/knowledge_base`, он на постоянном
диске. Два способа наполнить:

**Через панель Amvera** (без пересборки) — раздел **Данные**, загрузить файлы
в `knowledge_base/`. Индекс подхватит их автоматически, перезапуск не нужен.

**Через git** — положить документы в `knowledge_base/` репозитория и запушить.
При первом запуске, если диск пуст, они переносятся на него автоматически
(см. `docker-entrypoint.sh`). Дальше приоритет у диска: чтобы обновить документ,
меняйте его на диске либо очистите каталог перед передеплоем.

Структура разделов и шаблоны — в [`knowledge_base/README.md`](knowledge_base/README.md).

## Шаг 5. Google Drive и Calendar

Workspace и прохождение верификации не нужны: приложение личного
использования работает без проверки. Важно другое — **не оставлять статус
Testing**, иначе выданные согласия протухают через семь дней.

### В Google Cloud Console

1. Создайте проект, включите **Google Drive API** и **Google Calendar API**.
2. *APIs & Services → Credentials → Create credentials → OAuth client ID*,
   тип **Desktop app**. Скачайте JSON в `credentials/client_secret.json`.
3. *OAuth consent screen* → **Publish app** (статус станет *In production*).
   **На верификацию не подавайте** — она нужна только для публичных
   приложений со многими пользователями.

При первом входе Google покажет экран «Приложение не проверено»:
«Дополнительные настройки» → «Перейти к …». Дальше токен живёт бессрочно,
пока вы сами не отзовёте доступ.

### Запрашиваемые разрешения

По умолчанию берётся минимум:

| Разрешение | Что даёт |
|---|---|
| `drive.readonly` | Поиск и чтение документов, таблиц, презентаций |
| `drive.file` | Создание файлов (протоколы, КП) и доступ **только** к тем, что создал агент |
| `calendar.events` | Чтение и создание событий (создание — по подтверждению) |

`drive.file` намеренно взят вместо полного `drive`: агент может создать файл
и работать со своими, но не может изменить или удалить остальной ваш Диск.

Списка календарей агент не запрашивает — работает с основным (`primary`).
Ради перечня календарей пришлось бы просить `calendar.readonly`, а у одного
человека рабочий календарь один.

**Менять набор — значит проходить авторизацию заново:** выданный токен
привязан к тем правам, которые были на момент согласия, и новых не получит.

### Авторизация: команда /auth в боте (основной способ)

Переносить файлы руками не нужно. На сервер достаточно положить
`client_secret.json` (в `/data/credentials/`) — дальше всё делается в чате:

1. отправьте боту `/auth`;
2. откройте присланную ссылку и разрешите доступ той учётной записи,
   с документами которой должен работать ассистент;
3. браузер попытается открыть `http://localhost:8765/` и покажет **ошибку
   соединения — это нормально**: слушать этот адрес некому;
4. скопируйте адрес из строки браузера целиком и пришлите его боту.

Токен сохранится на постоянный диск сам, уже зашифрованным. Бот покажет,
под какой учётной записью выдан доступ и какие разрешения получены, —
сверьте глазами. Так же выполняется и переавторизация: смена состава
scope'ов больше не требует доступа к серверу.

Адрес возврата меняется через `OPERON_OAUTH_REDIRECT_URI` (нужно, если
OAuth-клиент создан как «Web application», а не «Desktop app»).

### Авторизация локально (запасной способ)

```bash
export OPERON_TOKEN_KEY='ваша парольная фраза'
python -m app.integrations.google_auth
```

Токен сохранится **зашифрованным** — `credentials/google_token.json.enc`
плюс `credentials/token_salt.bin`. Загрузите **оба файла** через панель
Amvera в `/data/credentials/` и задайте на сервере ту же `OPERON_TOKEN_KEY`.

Без `OPERON_TOKEN_KEY` токен хранится открытым текстом, и любой, кто получит
доступ к диску, получит доступ к вашему Google-аккаунту.

## Шаг 6. Telegram-бот

1. У [@BotFather](https://t.me/BotFather) создайте бота, получите токен.
2. Свой Telegram ID узнайте у [@userinfobot](https://t.me/userinfobot).
3. Добавьте в переменные окружения Amvera:

```
TELEGRAM_BOT_TOKEN       <токен от BotFather>
TELEGRAM_ALLOWED_USERS   <ваш ID; несколько — через запятую>
```

Бот стартует вместе с приложением отдельным потоком, веб-интерфейс
продолжает работать. Поток работает под надзором: если бот упадёт или
оборвётся связь с Telegram, он поднимется сам — паузы между попытками
растут с 5 секунд до 5 минут, причина падения пишется в лог и видна
в `/api/health`.

**Белый список обязателен.** Без `TELEGRAM_ALLOWED_USERS` бот не запустится,
и это намеренно: он работает с вашим Google-аккаунтом и вашим бюджетом API,
поэтому доступ по знанию адреса бота недопустим. Сообщения от посторонних
игнорируются молча — бот не отвечает даже отказом, чтобы не подтверждать
своё существование.

В боте: обычный вопрос — текстом, подтверждения — кнопками
**Подтвердить / Правки / Отмена**. «Правки» отклоняет действие и просит
описать, что изменить. Команды: `/new`, `/status`, `/auth`, `/help`.

Карточка подтверждения живёт ограниченное время: без ответа за
`OPERON_CONFIRMATION_TTL_MINUTES` (по умолчанию 30) действие отменяется, и
модель узнаёт, что оно **не выполнено**. Это то же правило «нет ответа =
отказ», но наступающее само: иначе диалог, оставленный без ответа, замирал
бы навсегда. Поставьте `0`, чтобы срок не ограничивать.

## Особенности работы через сторонний шлюз

Три возможности — расширения Anthropic, и на чужом шлюзе они по умолчанию
**выключены**, потому что он не обязан их поддерживать:

| Возможность | Что вместо неё | Как включить, если шлюз умеет |
|---|---|---|
| Серверный веб-поиск Anthropic | собственные `internet_search` и `open_url` по ключу поискового API | `OPERON_WEB_SEARCH=true` |
| Параметр `effort` | глубина по умолчанию | `OPERON_USE_EFFORT=true` |
| Кэширование промпта | обычные запросы (дороже на длинных диалогах) | `OPERON_USE_PROMPT_CACHE=true` |

Если включить, а шлюз параметр не примет, агент это заметит: снимет именно
его и повторит запрос, а не упадёт. В логах будет строка «Провайдер … не
принял …».

**Интернет через сторонний шлюз требует своего ключа поиска.** Без него
`internet_search` честно сообщит, что внешние данные недоступны, и агент
ответит только по внутренним источникам — вместо того чтобы выдумывать
рыночные цифры. Достаточно одного из ключей: `TAVILY_API_KEY`,
`BRAVE_API_KEY`, `SERPER_API_KEY` либо пары `GOOGLE_CSE_KEY` + `GOOGLE_CSE_ID`.

## Обновление

```bash
git push amvera claude/operon-ai-agent-06p9uw:master
```

Данные на `/data` не затрагиваются. История диалогов хранится в памяти
процесса и очищается при перезапуске — это ожидаемо.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| «Отказ в запуске: … пароль не задан» | не задан `OPERON_ACCESS_PASSWORD` |
| «Не задан ключ доступа к модели» | нет `OPENROUTER_API_KEY` в переменных окружения |
| 404 от шлюза | неверный адрес или имя модели — запустите `python -m app.probe` |
