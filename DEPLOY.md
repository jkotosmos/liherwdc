# Развёртывание на Amvera Cloud

Приложение собирается по `Dockerfile`, поэтому окружение на сервере совпадает
с локальным. Всё изменяемое состояние лежит на постоянном диске `/data` и
переживает передеплой.

## Что понадобится

| Что | Где взять | Обязательно |
|---|---|:---:|
| Ключ RouterAI | личный кабинет [routerai.ru](https://routerai.ru/) | **да** |
| Точное имя модели | покажет `python -m app.probe` из вашего каталога | **да** |
| Пароль на вход | придумываете сами | **да** |
| Проект в Amvera | панель Amvera → «Создать проект» | **да** |
| Ключ поискового API | Tavily / Brave / Serper / Google CSE — для работы с интернетом | желательно |
| Документы базы знаний | ваши файлы (`.md`, `.csv`, `.json`) | позже |
| OAuth-клиент Google | Google Cloud Console | опционально |

### Проверка перед развёртыванием

RouterAI совместим с API OpenAI, адрес подставляется сам — достаточно ключа.
Убедитесь, что выбранная модель умеет вызывать инструменты:

```bash
export ROUTERAI_API_KEY=ваш-ключ
python -m app.probe
```

Проверка выведет каталог моделей вашего аккаунта, определит протокол и —
главное — покажет, работает ли **вызов инструментов**. Без него агент
бесполезен: он не сможет ни искать в базе знаний, ни спрашивать
подтверждение. Выберите модель из списка (у Claude вызов инструментов
поддерживается) и укажите её в `OPERON_MODEL`.

Если используете не RouterAI, а другой шлюз, задайте `OPERON_LLM_BASE_URL`
и `OPERON_LLM_API_KEY` — та же проверка подберёт протокол.

## Шаг 1. Переменные окружения

В панели Amvera: проект → **Переменные окружения**. Минимальный набор:

```
ROUTERAI_API_KEY         <ключ RouterAI>
OPERON_MODEL             <имя модели из app.probe>
OPERON_ACCESS_PASSWORD   <ваш пароль>
OPERON_PUBLIC_URL        https://<проект>.amvera.io
OPERON_ORG_NAME          OPERON
OPERON_TIMEZONE          Europe/Moscow
TAVILY_API_KEY           <ключ поиска, если нужен интернет>
```

Адрес (`https://routerai.ru/api/v1`) и протокол (`openai`) для RouterAI
подставляются автоматически — задавать их не нужно.

`OPERON_HOST`, `OPERON_PORT` и пути к данным уже заданы в `Dockerfile` —
задавать их в панели не нужно.

> Без `OPERON_ACCESS_PASSWORD` приложение **откажется запускаться** на внешнем
> адресе. Это намеренно: на сервере хранится OAuth-токен вашего Google-аккаунта,
> и чат без пароля означал бы открытый доступ к вашим документам и календарю.

## Шаг 2. Загрузка кода

Amvera даёт git-репозиторий проекта. Из каталога с кодом:

```bash
git remote add amvera https://git.amvera.ru/<логин>/<проект>
git push amvera claude/operon-ai-agent-06p9uw:master
```

Сборка стартует автоматически. Следите за ней во вкладке **Сборка**;
после успеха приложение поднимется на `https://<проект>.amvera.io`.

## Шаг 3. Проверка

```bash
curl https://<проект>.amvera.io/api/health     # {"status":"ok"} — без пароля
```

Откройте адрес в браузере: появится страница входа. После пароля —
чат. В шапке видно провайдера, число документов и состояние Google.

## Шаг 4. База знаний

Каталог базы знаний на сервере — `/data/knowledge_base`, он на постоянном
диске. Два способа наполнить:

**Через панель Amvera** (без пересборки) — раздел **Данные**, загрузить файлы
в `knowledge_base/`. Индекс подхватит их автоматически, перезапуск не нужен.

**Через git** — положить документы в `knowledge_base/` репозитория и запушить.
При первом запуске, если диск пуст, они переносятся на него автоматически
(см. `docker-entrypoint.sh`). Дальше приоритет у диска: чтобы обновить документ,
меняйте его на диске либо очистите каталог перед передеплоем.

Структура разделов и шаблоны — в [`knowledge_base/README.md`](knowledge_base/README.md).

## Шаг 5. Google Drive и Calendar (опционально)

На сервере нет браузера, поэтому OAuth проходится **локально**, а на сервер
переносится готовый токен.

1. Локально: положите `client_secret.json` в `credentials/` и выполните
   `python -m app.integrations.google_auth` — подтвердите доступ в браузере.
2. Получившийся `credentials/google_token.json` загрузите через панель Amvera
   в `/data/credentials/google_token.json`.
3. Перезапустите приложение. В шапке появится подключённый аккаунт.

Токен обновляется автоматически по refresh-токену; повторять процедуру нужно
только при отзыве доступа или смене состава разрешений.

## Особенности работы через сторонний шлюз

Три возможности — расширения Anthropic, и на чужом шлюзе они по умолчанию
**выключены**, потому что он не обязан их поддерживать:

| Возможность | Что вместо неё | Как включить, если шлюз умеет |
|---|---|---|
| Серверный веб-поиск Anthropic | собственные `internet_search` и `open_url` по ключу поискового API | `OPERON_WEB_SEARCH=true` |
| Параметр `effort` | глубина по умолчанию | `OPERON_USE_EFFORT=true` |
| Кэширование промпта | обычные запросы (дороже на длинных диалогах) | `OPERON_USE_PROMPT_CACHE=true` |

Если включить, а шлюз параметр не примет, агент это заметит: снимет именно
его и повторит запрос, а не упадёт. В логах будет строка «Провайдер … не
принял …».

**Интернет через сторонний шлюз требует своего ключа поиска.** Без него
`internet_search` честно сообщит, что внешние данные недоступны, и агент
ответит только по внутренним источникам — вместо того чтобы выдумывать
рыночные цифры. Достаточно одного из ключей: `TAVILY_API_KEY`,
`BRAVE_API_KEY`, `SERPER_API_KEY` либо пары `GOOGLE_CSE_KEY` + `GOOGLE_CSE_ID`.

## Обновление

```bash
git push amvera claude/operon-ai-agent-06p9uw:master
```

Данные на `/data` не затрагиваются. История диалогов хранится в памяти
процесса и очищается при перезапуске — это ожидаемо.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| «Отказ в запуске: … пароль не задан» | не задан `OPERON_ACCESS_PASSWORD` |
| «Не задан ключ доступа к модели» | нет `OPENROUTER_API_KEY` в переменных окружения |
| 404 от шлюза | неверный адрес или имя модели — запустите `python -m app.probe` |
| 401/403 от шлюза | ключ не принят или модель вне вашей подписки |
| Агент не вызывает инструменты | шлюз не поддерживает tool calling — проверьте `python -m app.probe` |
| «База знаний пуста» | документы не загружены на `/data/knowledge_base` |
| Google не подключён | нет `/data/credentials/google_token.json` |
