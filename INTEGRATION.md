# Стыковка с другими частями экосистемы OPERON

Этот сервис — ассистент: он отвечает на вопросы, работает с Диском и
календарём, ведёт поручения, показатели и протоколы, и **всё, что меняет
данные, выполняет только после подтверждения пользователя**.

Он не претендует на роль корпоративного хранилища знаний. Если такое
хранилище в экосистеме есть, ассистент должен читать из него, а не держать
рядом вторую копию документов.

## Почему это важно решить до наполнения базы

Две базы знаний в одной экосистеме — это две версии правды. Документ
обновили в одной, а ассистент ответил по другой; формально он не соврал, но
человек получил устаревшее условие договора и принял по нему решение.

Ровно этого требование ТЗ «отвечать со ссылкой на источник» и пытается не
допустить. Поэтому вариантов ровно три, и выбрать нужно один:

| Вариант | Когда подходит | Цена |
|---|---|---|
| **Только локальная база** | документов немного, обновляет их один человек | ничего не нужно от соседей |
| **Только внешняя база** | хранилище экосистемы уже есть и наполняется | нужен HTTP-интерфейс, описанный ниже |
| Обе сразу | — | **не рекомендуется**: расхождение неизбежно |

Сейчас работает первый вариант. Переход на второй — это переменные окружения
и один инструмент, переписывать агента не требуется.

## Что нужно от сервиса-хранилища

Три метода, по одному на каждый инструмент ассистента. Всё — `GET`, ответы
в JSON, кодировка UTF-8.

### 1. Поиск фрагментов

```
GET /search?q=<запрос>&limit=<число>
```

```json
{
  "results": [
    {
      "id": "doc-142#3",
      "title": "Договор поставки № 17/2026",
      "section": "Порядок оплаты",
      "text": "Срок оплаты — 30 календарных дней с даты подписания акта.",
      "citation": "Договор поставки № 17/2026, раздел «Порядок оплаты»",
      "updated": "2026-08-14",
      "url": "https://kb.operon…/documents/142",
      "score": 12.4
    }
  ]
}
```

**`citation` обязателен.** Без него ассистент не сможет выполнить требование
ТЗ и будет вынужден отвечать «источник неизвестен» — то есть смысл внешней
базы пропадёт. Если поля нет, ассистент соберёт ссылку из `title` и
`section`, но это хуже: формулировку ссылки лучше задавать хранилищу.

`url` необязателен, но полезен: по нему человек открывает документ целиком.

### 2. Документ целиком

```
GET /documents/<id>?section=<раздел>
```

```json
{
  "id": "doc-142",
  "title": "Договор поставки № 17/2026",
  "text": "…полный текст или текст одного раздела…",
  "sections": ["Предмет", "Порядок оплаты", "Ответственность"],
  "citation": "Договор поставки № 17/2026",
  "updated": "2026-08-14"
}
```

### 3. Состав базы

```
GET /documents?limit=<число>
```

```json
{
  "documents": [
    {
      "id": "doc-142",
      "title": "Договор поставки № 17/2026",
      "category": "Договоры",
      "owner": "Иванов",
      "updated": "2026-08-14"
    }
  ],
  "total": 87
}
```

## Требования, о которых легко забыть

**Пусто — это статус, а не ошибка.** Если ничего не найдено, отвечайте `200`
и пустым списком. Ассистент устроен так, что честно скажет «данных нет»; а
вот `500` он покажет пользователю как поломку интеграции.

**Права пользователя.** Ассистент работает от имени конкретного человека и не
должен видеть больше, чем видит он. Если в хранилище есть разграничение
доступа, интерфейс должен принимать идентификатор пользователя и фильтровать
выдачу по нему. Ассистент не будет пытаться обойти отказ — он передаст его
пользователю как есть.

**Аутентификация.** Заголовок `Authorization: Bearer <токен>`, токен сервиса
задаётся переменной окружения. Токен в URL не передаётся: он попадёт в логи.

**Таймаут.** Ассистент ждёт ответа не дольше 20 секунд. Долгая индексация
должна быть асинхронной и не блокировать поиск.

**Ошибку лучше объяснить, чем скрыть.** Тело ответа с ненулевым кодом вида
`{"error": "понятная причина"}` ассистент покажет пользователю. Пустой `500`
он покажет как «внешняя база знаний недоступна» — тоже честно, но бесполезно
для разбирательства.

## Что ассистент делает, если хранилища нет

Работает на локальной базе (`knowledge_base/` на постоянном диске) — так он
работает сейчас. Индексируются `.md`, `.txt`, `.csv`, `.tsv`, `.json`,
`.yaml`, а также `.docx`, `.pdf`, `.xlsx`, `.pptx`.

Если внешняя база настроена, но недоступна, ассистент не молчит и не
выдумывает: сообщает, что источник недоступен, и отвечает по локальной базе,
явно помечая это в ответе.

## Что ассистент отдаёт наружу сам

Сейчас — ничего, кроме собственного интерфейса: веб-чат и Telegram-бот.
Служебные точки: `GET /api/health` (состояние процесса и бота, без пароля),
`GET /api/status` (провайдер, база знаний, интеграции — под паролем).

Если экосистеме понадобится дёргать ассистента программно (например, чтобы
служба протоколов присылала расшифровку встречи на разбор), интерфейс
добавляется — но **шлюз подтверждений при этом не отключается**: действие,
меняющее данные, всё равно потребует явного согласия человека. Это
архитектурное свойство, а не настройка.
