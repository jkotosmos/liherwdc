# База знаний OPERON

Сюда кладутся внутренние документы компании. Всё, что лежит в этом каталоге,
индексируется при старте сервера и становится доступно ассистенту через
инструменты `kb_search`, `kb_get_document`, `kb_list_documents`.

**Каталог намеренно пуст.** Ассистент отвечает только по реальным данным: пока
здесь нет документов, на вопросы о компании он будет отвечать «в базе знаний нет
данных» — и это правильное поведение, а не сбой. Заполните базу своими файлами.

## Как добавить документ

1. Создайте файл в подкаталоге нужного раздела (см. структуру ниже).
2. Добавьте в начало файла блок метаданных — он повышает качество поиска
   и позволяет ассистенту корректно ссылаться на источник.
3. Перезагружать сервер не нужно: индекс пересобирается автоматически, как
   только меняются файлы.

```markdown
---
title: Тарифы для партнёров, 2026
category: тарифы
updated: 2026-03-01
owner: Коммерческий отдел
source: https://drive.google.com/file/d/.../view
---

# Тарифы для партнёров

## Базовые ставки
...
```

| Поле      | Назначение                                                        |
|-----------|-------------------------------------------------------------------|
| `title`   | Название документа в ответах ассистента                           |
| `category`| Раздел; если не указан — берётся имя подкаталога                   |
| `updated` | Дата актуальности. Ассистент предупредит, если документ устарел    |
| `owner`   | Владелец данных — к кому идти с вопросами                          |
| `source`  | Ссылка на первоисточник (Google Drive, CRM, портал)               |

## Структура разделов

```
knowledge_base/
├── biznes-model/     Бизнес-модель: как компания зарабатывает, юниты, каналы
├── produkty/         Продукты и услуги: состав, границы, ограничения
├── partnery/         Партнёры: роли, условия, контакты, статус отношений
├── dogovory/         Договоры: стороны, предмет, сроки, ключевые обязательства
├── processy/         Регламенты и процессы: кто, что, в какой последовательности
├── tarify/           Тарифы и ценообразование: ставки, скидки, правила применения
├── kpi/              Показатели: определения, формулы, плановые значения, факт
├── zadachi/          Текущие задачи и проекты: статусы, ответственные, сроки
└── _templates/       Пустые формы (в индекс НЕ попадают)
```

Разделы можно переименовать или добавить свои — ассистент читает фактическую
структуру каталогов, жёсткой привязки к этим именам нет.

## Форматы файлов

Индексируются: `.md`, `.txt`, `.csv`, `.tsv`, `.json`, `.yaml`, `.yml`.

- **Markdown** — основной формат. Заголовки `##` становятся разделами, и
  ассистент ссылается на конкретный раздел, а не на файл целиком.
- **CSV/TSV** — таблицы (тарифные сетки, реестры партнёров, план-факт по KPI).
  Первая строка должна быть заголовком.
- **JSON/YAML** — структурированные справочники.

PDF и `.docx` не индексируются. Экспортируйте их в Markdown или храните в
Google Drive — ассистент прочитает их оттуда инструментом `drive_read`.

## Что не стоит сюда класть

- Персональные данные и учётные данные (пароли, ключи, токены).
- Файлы, к которым у читателей ассистента не должно быть доступа: в этой базе
  нет разграничения прав — всё, что здесь лежит, доступно любому пользователю
  ассистента. Разграниченные по правам документы держите в Google Drive, где
  ассистент видит их только под учётной записью конкретного пользователя.

## Каталог `_templates`

Формы для заполнения — какие поля стоит указать в документе каждого типа.
Из индексации исключены намеренно: пустой шаблон не должен попадать в ответы
как факт. Скопируйте нужный шаблон в рабочий раздел и заполните.
