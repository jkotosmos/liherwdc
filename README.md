# Деловой ИИ-ассистент OPERON

Чат-бот на Claude (Anthropic API), который работает с внутренними данными
компании, Google Drive, Google Calendar и открытыми источниками — и отвечает
со ссылкой на источник каждого факта.

Ключевое свойство: **ассистент не придумывает данные и ничего не меняет без
подтверждения.** Если сведений нет — он так и говорит, а не заполняет пробел
правдоподобным текстом.

```
┌──────────────┐          ┌───────────────┐                  ┌──────────┐
│  Telegram    │ ───────► │  FastAPI      │ ───────────────► │  Модель  │
│  (кнопки)    │ ◄─────── │  + агент      │ ◄─────────────── │  (шлюз)  │
├──────────────┤          └───────┬───────┘                  └──────────┘
│  Веб-чат     │ ◄──SSE───────────┤ инструменты
└──────────────┘                  ▼
      ▲  карточка       ┌─────────────────────────────────────────────┐
      │  подтверждения  │ база знаний · Google Drive · Google Calendar │
      └──── ждём ─────  │ реестр поручений · интернет-поиск           │
            решения     └─────────────────────────────────────────────┘
```

## Что умеет

**Знает проект OPERON.** Ищет по локальной базе знаний (бизнес-модель, продукты,
партнёры, договоры, процессы, тарифы, KPI, задачи) полнотекстовым поиском с учётом
русской морфологии: запрос «тарифы партнёров» находит документ со словами «тариф
партнёра». В ответе указывает файл, раздел и дату обновления.

**Работает с Google Drive.** Находит и читает документы, таблицы (полистно) и
презентации, показывает историю версий и построчно сравнивает две редакции —
что добавилось и что убрали. Готовит сводки, расчёты, коммерческие предложения
и проекты документов; по подтверждению создаёт файл на Диске.

**Работает с Google Calendar.** Показывает встречи и сроки, создаёт события и
напоминания — после подтверждения. Предупреждает, когда участникам уйдут
приглашения.

**Ведёт себя как бизнес-ассистент.** Фиксирует поручения с ответственными и
сроками, показывает просрочки, готовит протоколы встреч и списки следующих
действий, анализирует показатели и объясняет отклонения.

**Использует интернет.** Ищет данные о рынке, конкурентах, законодательстве и
технологиях, приводит ссылки и дату получения — и отделяет внешние данные от
внутренних. При прямом доступе к Anthropic используется её серверный поиск,
через сторонний шлюз — собственные инструменты по ключу поискового API
(Tavily, Brave, Serper или Google CSE).

## Интерфейсы

**Telegram** — основной. Подтверждения приходят кнопками
«Подтвердить / Правки / Отмена», бот может писать сам (напоминания).
Доступ ограничен белым списком Telegram ID: сообщения от всех остальных
игнорируются молча. Без списка бот не запускается.

**Веб-чат** — тот же агент в браузере, вход по паролю. Удобен для длинных
ответов и просмотра источников.

Оба интерфейса работают одновременно в одном процессе и делят базу знаний,
реестр поручений и подключение к Google.

## Как устроены гарантии

| Требование | Как обеспечено |
|---|---|
| Не придумывать данные | Ответы строятся только на результатах инструментов. Пустой результат возвращает модели явное указание: «данных нет, не выдумывай». Системный промпт запрещает достраивать суммы, даты, имена и номера договоров |
| Указывать источник | Каждый инструмент возвращает готовую ссылку на источник (файл + раздел + дата, либо ссылка Drive, либо URL и дата публикации) |
| Разделять внутреннее и внешнее | Три источника (внутренние данные, интернет, собственные выводы) описаны в промпте как разные категории, смешивать их в одном утверждении запрещено |
| Уточняющие вопросы | Промпт задаёт критерий: спрашивать, когда разные трактовки приведут к принципиально разной работе; в остальных случаях — явно обозначенное допущение |
| Только права пользователя | Google-доступ по OAuth-токену конкретного человека. Сервисных аккаунтов с расширенными правами нет. Отказ Google (403) передаётся пользователю как есть |
| Защита интерфейса | Telegram — белый список ID, посторонние игнорируются молча, без списка бот не стартует. Веб — пароль и подписанная HMAC-кука с ограничением подбора; приложение отказывается слушать внешний адрес без пароля |
| Токен Google на сервере | Шифруется на диске (scrypt + Fernet) при заданном `OPERON_TOKEN_KEY`: доступ к диску сервера сам по себе не даёт доступа к Google-аккаунту |
| Подтверждение изменений | Инструмент объявляет `requires_confirmation=True`; рантайм **не выполняет** такой вызов, а останавливает ход и показывает карточку. Выполнение возможно только после явного «Подтвердить» |

Шлюз подтверждений устроен так, что забыть про него нельзя: решение принимает
рантайм по флагу инструмента, а не модель по тексту промпта. Отсутствие ответа
трактуется как отказ. Тест `test_missing_decision_defaults_to_reject` фиксирует
это поведение, `test_every_write_tool_is_gated` — что новый изменяющий инструмент
не проскочит мимо шлюза.

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env            # укажите ключ доступа к модели
python run.py                   # http://127.0.0.1:8000
```

Доступ к модели — через любой шлюз, код агента одинаков:

| Канал | Переменные | Когда |
|---|---|---|
| **RouterAI** | `ROUTERAI_API_KEY`, `OPERON_MODEL` | оплата из России; адрес и протокол подставляются сами |
| Другой шлюз | `OPERON_LLM_BASE_URL`, `OPERON_LLM_API_KEY`, `OPERON_MODEL` | любой OpenAI- или Anthropic-совместимый |
| OpenRouter | `OPENROUTER_API_KEY`, `OPERON_MODEL=anthropic/claude-opus-4.1` | оплата по токенам |
| Anthropic напрямую | `ANTHROPIC_API_KEY`, `OPERON_MODEL=claude-opus-5` | есть прямой доступ |

Поддерживаются оба протокола — Anthropic Messages API и OpenAI Chat
Completions. Не знаете, что у вашего провайдера? Проверка определит сама
и заодно скажет, умеет ли шлюз вызывать инструменты (без этого агент
работать не сможет):

```bash
python -m app.probe
```

Соответствие каждому пункту ТЗ расписано в [`TZ-COMPLIANCE.md`](TZ-COMPLIANCE.md).

**Развёртывание на сервере — [`DEPLOY.md`](DEPLOY.md)** (Amvera Cloud, Docker,
постоянный диск, перенос токена Google).

Посмотреть работу на вымышленных данных, не подключая ничего:

```bash
OPERON_KB_DIR=examples/demo_kb python run.py
```

## База знаний

Положите документы в `knowledge_base/` — индекс собирается при старте и
обновляется автоматически при изменении файлов. Структура разделов, формат
метаданных и готовые шаблоны (продукт, партнёр, договор, процесс, KPI, тариф,
бизнес-модель, проект) описаны в [`knowledge_base/README.md`](knowledge_base/README.md).

Каталог поставляется пустым намеренно: в репозитории нет ни одного придуманного
факта об OPERON. Пока документов нет, ассистент честно отвечает «в базе знаний
нет данных» — это ожидаемое поведение.

Индексируются `.md`, `.txt`, `.csv`, `.tsv`, `.json`, `.yaml`, а также офисные
форматы: **`.docx`, `.pdf`, `.xlsx`, `.pptx`**. Markdown режется по заголовкам,
Word — по абзацам и таблицам, Excel — по листам, PDF — по страницам, поэтому
ссылка ведёт на конкретный раздел, а не на файл целиком.

Разбор идёт внутри процесса, без внешних сервисов. Что не читается: сканы без
текстового слоя (распознавания изображений нет) и устаревшие `.doc`/`.xls` —
на них агент отвечает не «файл пуст», а просит пересохранить в новый формат.

## Место в экосистеме

OPERON — экосистема, этот сервис делается как её самостоятельная часть по
собственному ТЗ. Он ни от кого не зависит и ни к чему не подключается:
своя база знаний, своё хранилище поручений, свой доступ к Google.

Если экосистеме понадобится дёргать ассистента программно, интерфейс можно
добавить — но **шлюз подтверждений при этом не отключается**: действие,
меняющее данные, всё равно требует явного согласия человека. Это свойство
архитектуры, а не настройка.

## Google Drive и Calendar

Workspace и верификация приложения не нужны — личное использование работает
без проверки. Но статус **Testing оставлять нельзя**: согласия в нём
протухают через семь дней. В Google Cloud Console нажмите **Publish app**
(станет *In production*), на верификацию не подавайте. Один раз увидите
экран «Приложение не проверено» → «Дополнительные настройки» → «Перейти».

Разрешения по умолчанию — минимальные:

| Разрешение | Что даёт |
|---|---|
| `drive.readonly` | Поиск и чтение документов, таблиц, презентаций |
| `drive.file` | Создание файлов и доступ **только** к созданным агентом |
| `calendar.events` | Чтение и создание событий (создание — по подтверждению) |

Полный `drive` не запрашивается: агент создаёт протоколы и КП, но не может
тронуть остальной Диск. Списка календарей тоже нет — работа идёт с основным,
а ради перечня пришлось бы просить `calendar.readonly`.

**Смена набора scope'ов = новая авторизация:** выданный токен привязан к
правам, которые были на момент согласия.

### Подключение: команда `/auth`

Клиент задаётся переменными `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`
(или файлом `client_secret.json`). Дальше — прямо в Telegram, без доступа
к серверу. Сценарий зависит от типа OAuth-клиента:

**Web application** — в консоли зарегистрирован адрес
`<публичный адрес>/oauth2/callback`:

```
/auth  →  открыть ссылку  →  разрешить доступ  →  готово
```

Код приходит на сервер сам, бот пишет, что токен сохранён.

**Desktop app** — регистрировать нечего, но код придётся перенести руками:

```
/auth  →  открыть ссылку  →  разрешить доступ
       →  браузер покажет ошибку соединения (так и задумано)
       →  скопировать адрес из строки браузера и прислать боту
```

Токен в обоих случаях сохраняется на сервере зашифрованным; бот показывает,
под какой учётной записью выдан доступ и какие разрешения получены. Так же
проходит и переавторизация — переносить файлы не нужно.

Запасной способ, локально:

```bash
export OPERON_TOKEN_KEY='парольная фраза'
python -m app.integrations.google_auth
```

Токен сохраняется зашифрованным (`google_token.json.enc` + `token_salt.bin`).
Оба файла переносятся на сервер, там задаётся та же `OPERON_TOKEN_KEY`.
Без неё токен лежит открытым текстом — на сервере это означает, что доступ
к диску равен доступу к вашему Google-аккаунту. Шифрование защищает от
утёкшего бэкапа диска, но не от скомпрометированного процесса: ключ лежит
в переменных окружения той же машины.

Без настройки Google ассистент работает: инструменты `drive_*` и `calendar_*`
возвращают инструкцию по подключению, и модель предупреждает пользователя
вместо того, чтобы имитировать результат.

## Настройки

Все параметры задаются через `.env` или переменные окружения — полный список с
пояснениями в [`.env.example`](.env.example). Чаще всего меняют:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `OPENROUTER_API_KEY` | — | Ключ OpenRouter (или `ANTHROPIC_API_KEY` для прямого доступа) |
| `OPERON_MODEL` | по провайдеру | `anthropic/claude-opus-4.1` для OpenRouter, `claude-opus-5` для Anthropic |
| `OPERON_ACCESS_PASSWORD` | — | Пароль на вход. Обязателен при доступе извне |
| `OPERON_EFFORT` | `high` | Глубина работы: `low`…`max`. Только при прямом доступе к Anthropic |
| `OPERON_KB_DIR` | `knowledge_base` | Каталог базы знаний |
| `OPERON_TIMEZONE` | `Europe/Moscow` | Часовой пояс для дат и календаря |
| `OPERON_LLM_BASE_URL` | — | Адрес шлюза, если провайдер сторонний |
| `OPERON_LLM_PROTOCOL` | по провайдеру | `openai` или `anthropic` — определяется `app.probe` |
| `TAVILY_API_KEY` и др. | — | Ключ поиска для работы с интернетом через сторонний шлюз |
| `OPERON_GOOGLE_SCOPES` | `drive.readonly` + `drive.file` + `calendar.events` | Права доступа к Google. Смена набора требует повторного `/auth` |
| `OPERON_CONFIRMATION_TTL_MINUTES` | `30` | Сколько ждать ответа на подтверждение; без ответа действие отменяется. `0` — не ограничивать |
| `OPERON_DIGEST_HOUR` | `9` | Час утренней сводки о просрочках и встречах |
| `OPERON_QUIET_HOURS` | `22-8` | Часы, когда бот молчит |
| `OPERON_REMINDERS` | `true` | Напоминания целиком |
| `TELEGRAM_ALLOWED_USERS` | — | Белый список Telegram ID. Без него бот не запускается |

## Разработка

На Windows путь внутри venv — `.venv\Scripts\python.exe`, и `&&` в PowerShell 5
не работает: команды вводятся по одной. Подробнее — в [`DEPLOY.md`](DEPLOY.md).

```bash
python -m app.selfcheck         # заработает ли всё прямо сейчас (живые сервисы)
python -m app.acceptance        # прогон по пунктам ТЗ (отчёт для заказчика)
python -m pytest tests/ -q      # 397 тестов, ~5 с
python run.py --reload          # автоперезапуск
```

`app.selfcheck` обращается к настоящим сервисам и говорит, что именно чинить.
Коды возврата: `2` — не запустится, `1` — запустится, но часть функций не
работает, `0` — годен. Тесты доказывают, что код делает задуманное; самопроверка
отвечает на другой вопрос — приняли ли ключ, дошли ли до сети, выдал ли Google
нужные разрешения.

Структура:

```
app/
├── agent.py          Цикл работы с Claude, шлюз подтверждений
├── server.py         HTTP + SSE
├── prompts.py        Системный промпт и рантайм-контекст
├── sessions.py       Диалоги в памяти процесса
├── config.py         Настройки из окружения
├── storage.py        Атомарная запись JSON
├── auth.py           Пароль на вход и подписанные куки
├── llm.py            Бэкенды шлюзов: Anthropic и OpenAI-совместимый
├── probe.py          Диагностика подключения к шлюзу
├── telegram/         Бот: белый список, кнопки подтверждения, разметка
├── integrations/     OAuth Google и шифрование токена на диске
├── kb/               Индексация и BM25-поиск с русской морфологией
├── tools/            Инструменты: база знаний, Drive, Calendar, поручения
└── integrations/     OAuth и клиент Google API
static/               Интерфейс чата (без сборки и зависимостей)
tests/                Тесты, включая сценарии шлюза подтверждений
```

Цикл вызова инструментов написан вручную, а не на SDK-хелпере `tool_runner`:
подтверждение приходит отдельным HTTP-запросом, поэтому ход нужно заморозить
между запросами и возобновить с сохранённого состояния.

### Добавить свой инструмент

```python
from app.tools.base import Preview, ToolSpec, registry

registry.register(ToolSpec(
    name="crm_find_deal",
    description="Ищет сделку в CRM по названию клиента. Возвращает статус, сумму, этап.",
    input_schema={"type": "object",
                  "properties": {"client": {"type": "string"}},
                  "required": ["client"]},
    handler=lambda payload: crm.search(payload["client"]),
    activity="Ищу сделку в CRM",
    # для изменяющих действий:
    # requires_confirmation=True,
    # preview=lambda p: Preview(title="Изменить сделку", summary="…", details={…}),
))
```

Импортируйте модуль в `app/tools/__init__.py` — инструмент попадёт и в запрос к
модели, и в шлюз подтверждений. Возвращайте из обработчика словарь: он будет
сериализован в JSON для модели. Для ожидаемых ошибок бросайте `ToolError` —
модель получит текст и сможет объяснить его пользователю.

## Ограничения

- **История диалога живёт в памяти процесса** и теряется при перезапуске.
  Ответы Claude содержат блоки рассуждений с подписями, которые API требует
  возвращать без изменений; сериализовать их вручную рискованно. Реестр
  поручений и база знаний, разумеется, хранятся на диске.
- **Нет разграничения прав внутри базы знаний**: всё, что лежит в
  `knowledge_base/`, доступно любому пользователю ассистента. Документы с
  ограниченным доступом держите в Google Drive — там права проверяет Google под
  учётной записью конкретного человека.
- **Учётная запись одна на всех**: вход по общему паролю, отдельных
  пользователей и ролей нет. Все, кто знает пароль, работают с одним и тем же
  Google-аккаунтом и одним реестром поручений.
- **PDF и `.docx` не разбираются локально** — только через Google Drive.
- Поиск по базе знаний — лексический (BM25 + стемминг). Он не находит документы
  по смыслу, если в них нет слов запроса или их однокоренных форм.
